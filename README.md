# بوت الرد التلقائي لمتجر الملابس — دليل التشغيل الكامل

بوت بلغة Python (Flask) يرد تلقائياً بالذكاء الاصطناعي (Google Gemini) على:

| المنصة | ماذا يفعل |
|---|---|
| **Facebook Messenger** | يرد على رسائل الصفحة الخاصة، ويتذكر سياق المحادثة |
| **تعليقات فيسبوك** | رد عام قصير تحت التعليق + رسالة خاصة بالتفاصيل لصاحب التعليق (Private Reply) |
| **Instagram Direct** | يرد على رسائل حساب إنستغرام المرتبط بالصفحة |
| **تعليقات إنستغرام** | رد عام قصير + رسالة خاصة بالتفاصيل |

**حماية مدمجة:** التحقق من توقيع Meta، ومنع الرد المكرر، ومنع الرد على تعليقات الصفحة نفسها، والتحويل إلى موظف، وحد أقصى للردود في الساعة، والرد فقط من بيانات المتجر بدون اختراع أسعار.

## 1. ملفات المشروع

```
app.py            ← البوت كاملاً (الخادم + Webhooks + Gemini + الإرسال)
requirements.txt  ← المكتبات المطلوبة
.env.example      ← قائمة متغيرات البيئة (للمرجع فقط، لا تضع فيه أسراراً حقيقية)
README.md         ← هذا الدليل
```

## 2. تعديل بيانات متجرك

افتح `app.py` وابحث عن القسم: **`2) بيانات المتجر`**. عدّل القيم داخل `STORE`:

- `name`, `phone`, `whatsapp`, `address`, `working_hours`
- `payment_methods` و `return_policy` و `how_to_order`
- `delivery`: سطر لكل محافظة أو منطقة (`area`, `fee`, `duration`)
- `products`: لكل منتج `name`, `price`, `sizes`, `colors`, `fabric`, `in_stock`

> ⚠️ **مهم:** البوت لا يذكر أي سعر أو مقاس أو لون غير مكتوب هنا. إذا نفد منتج اجعل `"in_stock": False`.
> البيانات الموجودة حالياً **مثال فقط** — استبدلها ببيانات متجرك قبل التشغيل.

يمكنك أيضاً تعديل الرسائل الجاهزة تحت القسم نفسه: `HANDOFF_MESSAGE` (رسالة التحويل لموظف)، `ATTACHMENT_MESSAGE` (عند إرسال صورة)، `FALLBACK_MESSAGE` (عند خلل في الذكاء الاصطناعي).

## 3. الحصول على مفتاح Gemini

1. ادخل إلى **https://aistudio.google.com** بحساب Google.
2. اضغط **Get API key** ← **Create API key**.
3. انسخ المفتاح واحفظه — هذا هو `GEMINI_API_KEY`.

> النموذج الافتراضي في البوت: `gemini-3.5-flash-lite` (الأسرع والأرخص للدردشة حسب توثيق Google). يمكنك تغييره عبر المتغير `GEMINI_MODEL`.
> ملاحظة: في الخطة المجانية قد تستخدم Google البيانات لتحسين خدماتها، وتوجد حدود يومية للطلبات.

## 4. رفع المشروع إلى GitHub

Render يسحب الكود من GitHub.

1. أنشئ حساباً على **https://github.com** إن لم يكن لديك.
2. اضغط **+** (أعلى اليمين) ← **New repository** ← اكتب اسماً مثل `store-bot` ← اختر **Private** ← **Create repository**.
3. اضغط **uploading an existing file** ← اسحب الملفات: `app.py` و `requirements.txt` و `README.md` و `.env.example`.
4. اضغط **Commit changes**.

> ⛔ لا ترفع أبداً ملفاً فيه مفاتيحك الحقيقية. الأسرار تُكتب في Render فقط (الخطوة التالية).

## 5. النشر على Render مجاناً

1. ادخل إلى **https://render.com** وسجّل بحساب GitHub.
2. اضغط **New +** ← **Web Service** ← اختر المستودع `store-bot` ← **Connect**.
3. املأ الإعدادات:

| الحقل | القيمة |
|---|---|
| Name | `store-bot` (أو أي اسم) |
| Language / Runtime | **Python 3** |
| Branch | `main` |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `gunicorn app:app --workers 1 --threads 8 --timeout 120` |
| Instance Type | **Free** |

4. في قسم **Environment Variables** أضف المتغيرات (التفاصيل في [القسم 7](#7-متغيرات-البيئة-environment-variables)). في البداية يكفي: `VERIFY_TOKEN` و `GEMINI_API_KEY` — والباقي تضيفه بعد إعداد Meta.
5. اضغط **Deploy Web Service** وانتظر حتى ترى **Live**.
6. انسخ رابط خدمتك من أعلى الصفحة، مثل: `https://store-bot-xxxx.onrender.com`
7. افتح في المتصفح: `https://store-bot-xxxx.onrender.com/health` — يجب أن ترى `"status": "ok"`.

> **لماذا `--workers 1`؟** البوت يحفظ سياق المحادثات في الذاكرة، ووجود أكثر من عامل يفرّق الذاكرة. `--threads 8` يكفي للتعامل مع عدة رسائل معاً.

### ⚠️ مشكلة نوم الخادم في الخطة المجانية (مهم جداً)

حسب توثيق Render: الخدمة المجانية **تنام بعد 15 دقيقة بدون زيارات**، وتحتاج **حوالي دقيقة** لتستيقظ. أثناء ذلك قد تفشل أول رسالة من Meta (تعيد Meta المحاولة، لكن قد يتأخر الرد).

**الحل الشائع:** خدمة مراقبة مجانية تزور البوت كل 10 دقائق فلا ينام:
1. سجّل في **https://uptimerobot.com** (أو **https://cron-job.org**).
2. أضف مراقبة HTTP(s) للرابط: `https://store-bot-xxxx.onrender.com/health` كل **10 دقائق**.

> الخطة المجانية في Render تعطي **750 ساعة شهرياً**، وهي تكفي لخدمة واحدة تعمل طوال الشهر (حوالي 744 ساعة). لا تشغّل خدمة مجانية ثانية دائمة في نفس الحساب وإلا تنفد الساعات.

## 6. إعداد تطبيق Meta والـ Webhooks

### المتطلبات قبل البدء
- صفحة فيسبوك أنت **مسؤول (Admin)** عليها.
- حساب إنستغرام **احترافي** (Business أو Creator) **مرتبط بالصفحة** (من إعدادات الصفحة ← الحسابات المرتبطة).
- في تطبيق إنستغرام على الهاتف: **الإعدادات ← الرسائل والردود على القصص ← أدوات التحكم بالرسائل ← الأدوات المتصلة ← السماح بالوصول إلى الرسائل** (حتى تصل رسائل الدايركت للبوت).

> واجهة Meta تتغير كثيراً، فقد تختلف أسماء الأزرار قليلاً عما هو مكتوب هنا. المبدأ يبقى نفسه.

### الخطوة 1: إنشاء التطبيق
1. ادخل إلى **https://developers.facebook.com** ← **My Apps** ← **Create App**.
2. اختر حالة الاستخدام المتعلقة بالتواصل مع العملاء عبر **Messenger** و**Instagram** (أو نوع التطبيق **Business**).
3. أكمل الإنشاء واربطه بحساب أعمالك (Business Portfolio) إن طُلب.

### الخطوة 2: App ID و App Secret
- **App settings ← Basic**:
  - **App ID** ← ضعه في `META_APP_ID`.
  - **App Secret** ← اضغط **Show** ← ضعه في `APP_SECRET` على Render.
  - **Privacy Policy URL** ← اكتب: `https://store-bot-xxxx.onrender.com/privacy` (البوت يوفر صفحة سياسة خصوصية جاهزة — راجع نصها في `app.py`).

### الخطوة 3: رمز وصول الصفحة (Page Access Token) و Page ID
1. من إعدادات **Messenger** (أو **Messenger API Settings**) في لوحة التطبيق ← قسم **Access Tokens** / **Generate access tokens**.
2. اضغط **Connect / Add Page** واختر صفحتك ووافق على كل الصلاحيات.
3. اضغط **Generate** بجانب الصفحة ← انسخ الرمز ← ضعه في `PAGE_ACCESS_TOKEN` على Render.
4. **Page ID**: يظهر بجانب اسم الصفحة في نفس القسم (أو من صفحتك ← حول ← شفافية الصفحة) ← ضعه في `PAGE_ID`.

> بعد إضافة المتغيرات في Render اضغط **Save Changes** — سيعيد Render تشغيل الخدمة تلقائياً.

### الخطوة 4: إعداد Webhook للصفحة (Messenger + تعليقات فيسبوك)
1. في إعدادات Messenger ← **Webhooks** ← **Add Callback URL**:
   - **Callback URL**: `https://store-bot-xxxx.onrender.com/webhook`
   - **Verify Token**: نفس قيمة `VERIFY_TOKEN` التي وضعتها في Render حرفياً.
   - اضغط **Verify and Save**. (إذا فشل: تأكد أن الخدمة Live وأن `VERIFY_TOKEN` متطابق تماماً.)
2. بجانب صفحتك اضغط **Add subscriptions** وفعّل الحقول:
   - `messages` — الرسائل الواردة
   - `messaging_postbacks` — ضغطات الأزرار
   - `message_echoes` — لمعرفة متى يرد موظف يدوياً فيتوقف البوت
   - `feed` — التعليقات على المنشورات

### الخطوة 5: إعداد Webhook لإنستغرام
1. من لوحة التطبيق افتح إعدادات **Instagram** (Instagram API / Messenger API for Instagram) ← **Webhooks**.
2. استخدم **نفس** Callback URL و Verify Token.
3. اشترك في الحقول: `messages` و `comments`.
4. تأكد أن حساب إنستغرام المرتبط بالصفحة ظاهر ومتصل.

### الخطوة 6: الصلاحيات المطلوبة

| الصلاحية | لماذا |
|---|---|
| `pages_messaging` | استقبال وإرسال رسائل Messenger + الردود الخاصة على التعليقات |
| `pages_manage_metadata` | الاشتراك في Webhooks الصفحة |
| `pages_read_engagement` | قراءة تعليقات المنشورات |
| `pages_read_user_engagement` | قراءة تفاعلات المستخدمين مع الصفحة |
| `pages_manage_engagement` | الرد على التعليقات باسم الصفحة |
| `instagram_basic` | الوصول لحساب إنستغرام |
| `instagram_manage_messages` | رسائل إنستغرام Direct |
| `instagram_manage_comments` | قراءة تعليقات إنستغرام والرد عليها |

### الخطوة 7: وضع التطوير ثم المراجعة (App Review)
- **في وضع التطوير (Development):** البوت يرد **فقط** على الأشخاص الذين لهم دور في التطبيق (Admin / Developer / Tester). أضف حسابك وحساب صديق من **App roles ← Roles** للتجربة.
- **للرد على كل الزبائن:** تحتاج **Advanced Access** لهذه الصلاحيات عبر **App Review**:
  - صفحة سياسة خصوصية (موجودة: `/privacy`).
  - فيديو قصير يشرح كيف يستخدم البوت كل صلاحية.
  - غالباً **توثيق النشاط التجاري (Business Verification)**.
  - المراجعة قد تستغرق أياماً، وقد تُرفض أول مرة فتعدّل وتعيد التقديم.
- حسب توثيق Meta، الردود الخاصة على تعليقات إنستغرام تتطلب Advanced Access وميزة Human Agent أيضاً.
- بعد الموافقة حوّل التطبيق إلى **Live**.

## 7. متغيرات البيئة (Environment Variables)

تُضاف في Render: **خدمتك ← Environment ← Add Environment Variable**.

### إلزامية

| المتغير | القيمة | من أين |
|---|---|---|
| `VERIFY_TOKEN` | كلمة طويلة تختارها أنت (مثل `myStore_2026_xYz91`) | أنت — وتكتبها نفسها في Meta |
| `PAGE_ACCESS_TOKEN` | رمز وصول الصفحة | Meta ← إعدادات Messenger ← Access Tokens |
| `APP_SECRET` | المفتاح السري للتطبيق | Meta ← App settings ← Basic |
| `PAGE_ID` | رقم الصفحة | Meta أو صفحة «حول» في فيسبوك |
| `GEMINI_API_KEY` | مفتاح Gemini | aistudio.google.com |

### اختيارية

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `META_APP_ID` | فارغ | يساعد على تمييز رسائل البوت في إنستغرام عن ردود الموظفين |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | نموذج Gemini |
| `GRAPH_API_VERSION` | `v26.0` | إصدار Graph API |
| `ENABLE_MESSENGER` | `true` | الرد على رسائل Messenger |
| `ENABLE_FB_COMMENTS` | `true` | الرد على تعليقات فيسبوك |
| `ENABLE_INSTAGRAM_DM` | `true` | الرد على رسائل إنستغرام |
| `ENABLE_INSTAGRAM_COMMENTS` | `true` | الرد على تعليقات إنستغرام |
| `PUBLIC_COMMENT_REPLY` | `true` | رد عام تحت التعليق |
| `PRIVATE_REPLY_ON_COMMENT` | `true` | رسالة خاصة لصاحب التعليق |
| `REPLY_TO_COMMENT_REPLIES` | `false` | الرد على الردود داخل سلسلة التعليقات أيضاً |
| `BOT_DISCLOSURE_ENABLED` | `true` | إعلام الزبون في أول رد أنه يتحدث مع مساعد آلي |
| `MAX_REPLIES_PER_HOUR` | `200` | حد أقصى للردود في الساعة |
| `HANDOFF_PAUSE_HOURS` | `12` | مدة توقف البوت عن الزبون بعد تحويله لموظف |
| `HISTORY_MESSAGES` | `12` | عدد الرسائل السابقة التي يتذكرها البوت |
| `ALLOW_UNSIGNED_WEBHOOKS` | `false` | **للتجربة المحلية فقط** — لا تفعّله على Render |

> 🔒 **بدون `APP_SECRET` يرفض البوت كل طلبات Webhook** — هذا مقصود، حتى لا يستطيع أحد إرسال رسائل مزيفة لبوتك.

## 8. الاختبار

1. **الخادم:** افتح `https://store-bot-xxxx.onrender.com/health` وتأكد أن كل القيم في `config` هي `true`.
2. **Messenger:** من حساب له دور في التطبيق، أرسل لصفحتك: «بكم القميص؟».
3. **التعليقات:** علّق على منشور في الصفحة: «السعر؟» ← يجب أن يظهر رد عام تحت التعليق + رسالة خاصة في الماسنجر.
4. **إنستغرام:** أرسل رسالة Direct للحساب، وعلّق على منشور.
5. **التحويل لموظف:** اكتب «اريد موظف» ← يجب أن يرد برسالة التحويل ثم يتوقف عن الرد عليك.
6. **السجلات:** في Render ← خدمتك ← **Logs** ستظهر رسائل مثل `✅ تم الرد على رسالة messenger`.

### التشغيل على حاسوبك (اختياري)
```bash
pip install -r requirements.txt
# ضع المتغيرات في الطرفية أولاً، ثم:
python app.py
```
> Meta لا تصل إلى `localhost`؛ للتجربة المحلية مع Meta تحتاج نفقاً مثل ngrok. الأسهل: التجربة مباشرة على Render.

## 9. كيف يتصرف البوت

| الحالة | ماذا يفعل |
|---|---|
| زبون يسأل عن سعر/مقاس/لون/توصيل | يجيب من بيانات `STORE` فقط |
| المعلومة غير موجودة في البيانات | يعتذر ويحوّل لموظف (لا يخترع) |
| الزبون يكتب «موظف» أو «شخص حقيقي» | رسالة تحويل + يتوقف عن الرد على هذا الزبون 12 ساعة |
| الزبون يرسل صورة بدون نص | رسالة استلام + تحويل لموظف |
| صاحب الصفحة يرد يدوياً من صندوق الرسائل | البوت يتوقف عن الرد على هذا الزبون 12 ساعة |
| خلل في Gemini | رسالة اعتذار + تحويل لموظف |
| تعليق فيه رابط أو كلمات مسيئة | يتجاهله |
| تعليق من الصفحة نفسها | يتجاهله (منع الرد على نفسه بلا نهاية) |
| نفس الرسالة تصل مرتين من Meta | يرد مرة واحدة فقط |
| أول رد في المحادثة | يضيف سطراً يوضح أنه مساعد آلي |

## 10. حدود مهمة يجب أن تعرفها

- **نافذة 24 ساعة:** Meta تسمح بالرد على الزبون خلال 24 ساعة من آخر رسالة له فقط.
- **الرد الخاص على التعليق:** رسالة **واحدة فقط** لكل تعليق، وخلال **7 أيام** منه. بعدها يكمل الحديث إذا رد الزبون.
- **رسائل إنستغرام:** الحد 1000 بايت (حوالي 500 حرف عربي) — البوت يقسّم الرد الطويل تلقائياً.
- **الذاكرة مؤقتة:** سياق المحادثات وقائمة الزبائن المحوّلين لموظف تُمسح عند إعادة تشغيل الخادم أو نومه. للاستخدام الكبير تحتاج قاعدة بيانات.
- **خادم واحد فقط:** لا تزد عدد النسخ (instances) لأن الذاكرة غير مشتركة بينها.
- **تحديثات Meta:** إصدارات Graph API تنتهي صلاحيتها مع الوقت. عند انتهاء `v26.0` غيّر `GRAPH_API_VERSION` إلى الإصدار الأحدث.

## 11. حل المشكلات

| المشكلة | الحل |
|---|---|
| فشل **Verify and Save** في Meta | تأكد أن الخدمة Live، والرابط ينتهي بـ `/webhook`، و`VERIFY_TOKEN` متطابق حرفياً |
| في السجلات: `توقيع غير صالح` | `APP_SECRET` خاطئ — انسخه مجدداً من App settings ← Basic |
| في السجلات: `APP_SECRET غير مضبوط` | أضف `APP_SECRET` في Render |
| البوت لا يرد على زبائن عاديين | التطبيق في وضع التطوير — يرد فقط على أصحاب الأدوار حتى تحصل على Advanced Access |
| `Meta error 190` | رمز الصفحة منتهي أو خاطئ — أنشئ رمزاً جديداً |
| `Meta error 10` أو `200` | صلاحية ناقصة — راجع جدول الصلاحيات |
| `Meta error 10/2018278` | مرت 24 ساعة على آخر رسالة من الزبون |
| رسائل إنستغرام لا تصل | فعّل «السماح بالوصول إلى الرسائل» في تطبيق إنستغرام، وتأكد من الاشتراك في `messages` |
| `فشل Gemini` في السجلات | تحقق من `GEMINI_API_KEY`، أو تجاوزت الحد اليومي المجاني |
| أول رد يتأخر دقيقة | الخادم كان نائماً — فعّل مراقبة UptimeRobot (القسم 5) |
